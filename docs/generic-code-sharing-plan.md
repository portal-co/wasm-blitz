# Assembly-level generic code sharing plan

> Shadow plan — created 2026-09-20. This is a cross-repository change: the
> generic writer capability and its concrete binary-writer adapters live in
> `../asm-arch`; WASM safepoints, outlining policy, and end-to-end tests live
> here in `wasm-blitz`. Keep this document current as the design is proven and
> increments land. It is a plan, not an implemented interface.

## Goal

Make a writer able to remove the code it has already emitted after a known
label, hold that region as an **opaque code blob**, fingerprint the blob, and
append it again only when a caller decides it is needed. The immediate use is
WASM code-size reduction:

1. A backend automatically marks points at which its WASM stack, register
   allocator, frame, and control-flow state can safely cross an ordinary call.
2. It emits a candidate region normally, then drains the region from the
   assembly writer at its starting safepoint.
3. A per-compilation sharing coordinator groups candidates with the same
   code-blob fingerprint **and the same calling contract**.
4. Equivalent regions are emitted once as a generated helper; occurrences are
   replaced by backend-specific calls to that helper. The input WASM and its
   observable behavior do not change.

The writer capability is deliberately assembly-level. It knows bytes/text,
labels, instruction-boundary metadata, and fixups, but knows nothing of WASM,
register allocation, or which code is safe to call. Conversely, `wasm-blitz`
knows when a call is correct but must neither inspect nor mutate an opaque
blob's representation.

This is code **outlining**, not a WASM IR rewrite, source-level common
subexpression elimination, or an attempt to deduplicate arbitrary complete
functions. Initially it must be function-local and conservative. Cross-function
sharing is a later extension requiring an explicitly compatible frame and
helper ABI.

## Current facts and constraints

### Writer surface

`asm-arch` has one architecture-specific `out::Writer<L, Context>` trait per
architecture, on top of `WriterCore<Context>`:

- x86-64: `../asm-arch/crates/asm-x86-64/src/out.rs`
- AArch64: `../asm-arch/crates/asm-aarch64/src/out.rs`
- RV64/RV32: `../asm-arch/crates/asm-riscv{64,32}/src/out.rs`
- ARM and i686: `../asm-arch/crates/asm-{arm,x86}/src/out.rs`

The primary binary writers already own a byte buffer, a label-offset map, and
some form of forward-fixup state:

| ISA | Writer | File | Notable state |
| --- | --- | --- | --- |
| x86-64 | `IcedWriter<L>` | `asm-x86-64/src/out/iced.rs` | `buf`, `ip`, labels, rel32 fixups/relocations |
| AArch64 | `AArch64Writer<L>` | `asm-aarch64/src/out/bin.rs` | `buf`, labels, branch/ADR fixups/relocations |
| RV64/RV32 | `RvAsmWriter<L>` | `asm-riscv{64,32}/src/out/rv_asm_backend.rs` | `buf`, labels, JAL/LA/branch fixups |
| ARM | `ArmWriter<L>` | `asm-arm/src/out/bin.rs` | bytes and labels; label branches are not yet binary-relocatable |
| i686 | `IcedWriter<L>` | `asm-x86/src/out/iced.rs` | bytes, IP, labels; no forward-label fixup model yet |

Text output is currently a blanket `fmt::Write` implementation generated by
`writers!` macros. A generic `fmt::Write` cannot promise rewind or drain:
there is no way to undo bytes written to an arbitrary stream. It must not
silently claim this capability.

### wasm-blitz integration points

- `crates/blitz-common/src/sink.rs` owns `WaxHandle<W, AsmCtx>` and
  `WasmSink`; it is the generic path that carries a writer through compilation.
- `crates/blitz-codegen` is `#![no_std]` and already owns shared WASM codegen
  abstractions (`BlitzWriter`, `control_flow`, and `regalloc_frontend`). It is
  the right home for the WASM-only sharing coordinator and its tests.
- The active native backends have adapters in
  `crates/blitz-{x86-64,aarch64,riscv64,riscv32}/src/codegen.rs` and explicit
  ABI lowering in `abi.rs`, `naive.rs`, and/or `sysv.rs`.
- `State::label_index` already allocates `Indexed` labels. It must remain a
  monotonic identity allocator; drained labels may not be reused merely
  because their bytes are removed.
- `crates/blitz-tests/tests/e2e.rs` directly drives `IcedWriter`,
  `AArch64Writer`, and `RvAsmWriter` into Unicorn. This is the integration
  oracle for changed binary layout and generated calls.

The workspace's parent `../.cargo/config.toml` already owns local Cargo
patches. Do **not** add a repo-local `.cargo/config.toml` or override it. When
local cross-repo testing needs a patch for a new `asm-arch` crate or changed
architecture crates, make the minimal patch change in that parent config and
keep it out of either repository's commits unless the workspace owner asks to
commit it.

## Design: two deliberately separate modules

### 1. `asm-arch`: a small generic rewind/drain seam

Add a new independent crate to `../asm-arch`, tentatively
`crates/asm-writer` / package `portal-solutions-asm-writer`. It is preferable
to putting this into an ISA's `out` module or `asm-semantics`:

- it has no ISA, WASM, or `wax-core` dependency;
- it can remain `no_std`, using `alloc` only for concrete buffer adapters;
- it gives all architecture writers one shared vocabulary without forcing an
  artificial common architecture trait; and
- it avoids conflating instruction semantics with mutable output-buffer
  mechanics.

The module is a **deep module**: callers learn only a label-anchor operation,
a move-only opaque blob, append/discard, and a stable content fingerprint.
All byte slicing, `ip` rebasing, label ownership, fixup journals, relocation
rebasing, and hash normalization remain implementation details.

The exact names are subject to a compile-first spike, but the intended shape
is:

```rust
pub struct CodeHash(/* fixed, comparable 256-bit digest */);

pub trait RewindableCodeWriter<L> {
    type Blob;             // opaque: callers cannot access bytes or fixups
    type Error;

    /// Remove everything strictly after an already-placed `anchor` label and
    /// return it as a self-contained blob. The anchor remains at the current
    /// output position.
    fn drain_after(&mut self, anchor: &L) -> Result<Self::Blob, Self::Error>;

    /// Discard everything strictly after `anchor`. This has the same writer
    /// state effect as dropping the result of `drain_after`.
    fn rewind_after(&mut self, anchor: &L) -> Result<(), Self::Error>;

    /// Append a previously drained blob at the current output position,
    /// restoring/rebasing all of its private output metadata.
    fn append_blob(&mut self, blob: Self::Blob) -> Result<(), Self::Error>;

    /// A deterministic, process-independent fingerprint of the blob's
    /// canonical encoded form. It must not use `std::hash::Hash` plus a random
    /// `Hasher` as the sharing key.
    fn blob_hash(&self, blob: &Self::Blob) -> CodeHash;

    fn blob_len(&self, blob: &Self::Blob) -> usize;
}
```

`drain_after`, rather than an operation that consumes the anchor label, is
intentional. A candidate's anchor remains where the emitter will now write its
replacement call. The outlined helper receives a freshly allocated private
helper label immediately before `append_blob`; the candidate anchor is never
mistaken for that helper entry. This avoids a self-call and lets normal
`Writer<L, Context>::set_label` retain its existing meaning.

The trait is supplementary, **not** a supertrait of any existing
`WriterCore`/`Writer` trait. Existing streaming writers, tracing writers, and
all callers that do not want rewriting keep compiling unchanged. Desugaring
wrappers can forward it once their wrapped writer supports it, but only after
the base implementation is tested.

`CodeHash` is a fixed SHA3-256 digest, domain-separated by writer/ISA/encoding
version (for example `portal-solutions-asm-writer/x86-64/v1`). `asm-arch`
already has an appropriate workspace `sha3` dependency; use it rather than a
home-grown non-cryptographic mixer. The implementation supplies the domain
metadata. The stable digest is for in-process
keying and diagnostics, not a security boundary. The coordinator must still
verify byte/blob equivalence on a hash collision in debug/test builds before
sharing.

### 2. `wasm-blitz`: safepoints, contracts, and outlining decisions

Add a sharing module under `crates/blitz-codegen/src/` (tentatively
`code_sharing.rs`) rather than teaching `asm-writer` about WASM. Its public
surface should accept opaque blobs plus an emitter-provided `ShareContract`:

```rust
struct ShareContract {
    target: TargetEncodingAndFeatures,
    abi: GeneratedHelperAbi,
    frame_layout: FrameLayoutKey,
    operand_stack: OperandStackContract,
    locals: LocalStateContract,
    control_flow: ControlFlowContract,
    memory_and_sandbox: MemoryContract,
    instrumentation: InstrumentationContract,
}
```

The concrete representation can be compact and backend-local, but equality
must include every fact that changes the meaning of a call or generated bytes.
A blob hash alone is never sufficient: identical instruction bytes using a
frame offset, a context register, a memory index, or an LFI-reserved register
can be non-interchangeable.

The coordinator key is `(ShareContract, CodeHash, blob_len)`, followed by an
exact blob equality check supplied by the writer in assertions/tests. It owns
candidate accounting, profitability decisions, helper-label allocation, and
per-function reset. Backends own these hooks:

- place a safepoint anchor;
- flush/canonicalize state at the anchor and invalidate cached register state
  after a replacement call;
- emit a call to a generated helper label and any ABI-required save/restore;
- emit a non-fallthrough helper body (`append_blob` plus helper epilogue/ret)
  in a designated out-of-line area;
- state that a candidate is eligible or why it is rejected.

This division gives the generic assembly module leverage outside WASM while
keeping high-risk architecture/ABI rules local.

## Correctness model

### Safepoint eligibility

A backend may set an anchor freely, but it may only ask the coordinator to
outline a region if every condition below holds. Missing information means
**reject and leave the original code inline**.

1. **Single entry and single normal exit.** The region begins at the anchor,
   has no branch target, fallthrough entry, exception landing pad, `br_table`
   dispatch target, or externally visible label in its interior, and returns
   to the immediately following instruction only through the generated
   helper's normal return. A region that terminates, tail-calls, traps, throws,
   or branches may be supported later as a separate transfer contract, not as
   a v1 call candidate.
2. **Empty/canonical WASM operand stack.** In v1, the WASM value stack must be
   empty at entry and exit. The physical host stack is therefore not carrying
   operand values when the native call pushes a return address. Do not assume
   that adding a native `call` is harmless for the existing stack-machine
   lowerings.
3. **Canonical register state.** Flush `RegAlloc` state before the anchor,
   commit deferred local writes, and ensure no semantic WASM value depends on
   a caller-saved register after the call. Invalidate the allocator cache after
   the replacement call. The existing flush-before-control-flow and
   probe-scratch hazards documented in `docs/regalloc-unification-plan.md`
   are precedent for this rule.
4. **Compatible frame and locals.** The helper must use the caller's frame
   safely. v1 shares only within one generated function and requires the same
   fixed local/frame layout. Cross-function sharing additionally needs a
   parameterized helper ABI or a proven identical frame descriptor; it is out
   of scope.
5. **Call ABI is valid.** The backend proves stack alignment at the inserted
   call and inside nested calls in the helper, defines preservation/clobber
   behavior, and supplies a helper return sequence appropriate for x86-64,
   AArch64, RV64, and later ILP32 targets. Do not reuse a WASM function
   prologue/epilogue as a helper prologue by accident.
6. **No unsupported dynamic context.** Candidates may not cross probe sites,
   LFI bundles, active exception regions, multi-memory/table state that is not
   in the contract, stack maps, or future GC/safepoint metadata until each is
   explicitly represented in `ShareContract` and tested.
7. **No unsafe writer edges.** v1 candidates may not contain labels, internal
   or external branches, or unresolved relocations. The generic trait will
   support correct transactional writer state, but this initial restriction
   makes code identity position-independent and keeps the first rollout to
   straight-line code. Later phases can lift it with canonical local-label and
   relocation records.

These rules are deliberately strict. A rejected candidate is a successful
optimization miss, never a compiler error or a semantic change.

### Blob and label/fixup invariants

The trait cannot be implemented correctly as `buf.truncate(offset)` alone.
For each binary writer it must transactionally maintain:

- byte buffer and instruction cursor (`IcedWriter::ip` must be restored from
  the anchor offset, not merely decremented by a guessed instruction size);
- labels after the anchor, including duplicate-label diagnostics;
- unresolved forward fixups created after the anchor;
- fixups that were resolved when a later label was placed (the current writers
  patch and remove these, so the implementation needs a journal or a
  reconstructable fixup representation before it can rewind); and
- relocation records and patch locations when a blob is appended at a new
  offset.

A writer must reject an unknown anchor, an anchor not currently bound in this
writer, an attempt to append a blob into an incompatible writer/encoding, and
any range that has an incoming edge it cannot preserve. It must never leave a
partly-mutated writer on error. Define and test `drain_after` and
`rewind_after` as atomic operations.

For the initial straight-line subset, a blob contains only an instruction-boundary
byte range plus private provenance. Its digest includes an encoding version and
ISA. It excludes the surrounding byte offset, x86 `base_ip`, and the private
anchor/helper label identities. It must not hash raw already-patched
position-dependent branch displacements once branch-containing blobs are
introduced; those will require a canonical fixup stream.

## Layout and profitability: resolve before coding the automatic pass

A call-based extraction cannot safely leave the first occurrence inline and
later call into it: normal fallthrough code does not end in a helper `ret`.
The first occurrence must either be moved to a helper or the optimizer must
buffer enough output to make a final decision before emitting it. This is the
central layout constraint; do not hide it behind a hash map.

Implement and measure two strategies in a design spike, then choose one before
turning automatic sharing on:

1. **Per-function staging (preferred for production).** Compile eligible
   regions into a private function-local staging writer / blob sequence,
   discover equivalence classes, then emit ordinary inline singleton regions
   and one outlined helper plus calls for profitable classes. This realizes
   “only reinsert when needed”: singletons return to their original inline
   position, while repeated blobs are appended once to the function helper
   area. It needs a small function-finalization seam in `WasmSink`/backend
   lifecycle and forward label support, but it avoids code-size regressions
   for unique candidates.
2. **Immediate speculative outlining (spike/fallback only).** Drain every
   eligible region, emit a call, and emit a helper body in a branch-around or
   function trailer. It proves call/ABI correctness without staging but can
   make singleton code larger. Gate it behind an explicit experimental
   code-size mode and a minimum-size threshold; it is not the default result.

For either strategy, only share an equivalence class when measured bytes saved
are positive after counting: one helper label/body/return, every call,
necessary skip/section jump, alignment padding, and architecture-specific
long-call materialization. Add a minimum body-size threshold and a
per-function code-growth cap. If budget or eligibility is exhausted, restore
inline bytes and continue compilation.

Helpers are per-function in v1. Emit them in a dedicated helper area after the
normal function body (and after a branch/return that makes the area
unreachable by fallthrough), with labels distinct from `Func`, `Indexed`,
`External`, and `Ambient` labels. Generated labels should consume a separate
monotonic namespace/counter so normal `label_index` remains stable for control
flow and trace tests.

## Implementation sequence

### Phase 0 — record baselines and settle the contracts

1. Add focused baseline measurements to `wasm-blitz`: representative repeated
   straight-line integer WASM bodies, nonrepeating bodies, calls, branches,
   locals, and instrumentation-enabled functions. Record raw binary lengths
   per x86-64/AArch64/RV64 and existing execution results.
2. Write a compact architecture matrix covering native call instruction,
   helper return, caller/callee clobbers, stack alignment, frame-pointer use,
   regalloc flush/invalidate hooks, and unavailable registers for x86-64
   SysV/naive, AArch64, and RV64. Include LFI as explicitly unsupported.
3. Build a compile-only prototype of the trait signature in the new
   `asm-writer` crate and a mock writer. Decide the digest implementation,
   ownership semantics of `Blob`, exact error type, and whether a debug-only
   `blob_eq` method is needed. Do not yet modify production writers.
4. Choose staging versus immediate outlining based on a toy repeated/singleton
   benchmark. Document the decision and byte accounting in this file.

**Exit criterion:** exact trait and `ShareContract` equality rules are agreed;
no automatic transformation exists yet.

### Phase 1 — transactional binary writers in `asm-arch`

**Progress (2026-09-20):** the shared crate and the x86-64, AArch64, and RV64
binary implementations are complete behind their opt-in `rewindable-writer`
features. Each tracks both pending and resolved fixup recipes so moving a blob
can rebase backward references. All use a domain-separated SHA3-256 digest and
exact opaque-blob equality. RV32, forwarding desugaring adapters, and
unresolved-RISC-V-relocation surfacing remain pending.

1. Add `asm-writer` to `../asm-arch/Cargo.toml` workspace members and give it
   `no_std` defaults with an explicit allocation/hash feature.
2. Implement test-only/mock transactional writer coverage first: nested
   anchors; drain/append round trip; rewind; unknown anchor; atomic failure;
   stable digest; and a digest collision test that exercises equality fallback.
3. Implement x86-64 `IcedWriter<L>` first. Preserve/reconstruct `ip`, labels,
   `IcedFixup`, and `UnresolvedReloc` state. Test forward and backward label
   references around a drained range, every rel32 kind, append at a different
   offset, and final `into_parts_with_relocs` output.
4. Implement AArch64 `AArch64Writer<L>` next. Cover B/BL/B.cond/ADR,
   external ADRP+ADD relocation pairs, fixed four-byte alignment, and labels
   placed both before and after the anchor.
5. Bring RV64's and RV32's `RvAsmWriter<L>` to the same transactional model.
   As part of this work, expose unresolved relocations from the RISC-V binary
   writer consistently with x86-64/AArch64 instead of allowing pending
   fixups to disappear through `into_parts`; this is prerequisite correctness,
   not optional sharing scope.
6. Add the trait only to binary buffer writers initially. Add forwarding
   implementations to `DesugaringWriter` only once each relevant base writer
   passes the same tests. Do not add a dishonest blanket implementation for
   `fmt::Write`.
7. Leave ARM/i686 unsupported until their binary forward-label/fixup models
   exist. Their trait absence is an intentional capability boundary; document
   it and return to it after native 64-bit validation.

**Exit criterion:** each supported binary writer round-trips byte-for-byte and
metadata-for-metadata through `drain_after(anchor) + append_blob`, and its
existing crate tests pass unchanged.

### Phase 2 — WASM sharing plumbing, disabled by default

**Progress (2026-09-20):** `blitz-codegen::code_sharing` now provides a
disabled-by-default configuration, explicit `ShareContract`/`ShareKey`,
deterministic class accounting, profitability calculation, and unit tests.
It remains deliberately disconnected from backend emission pending the x86-64
SysV safepoint/helper vertical slice.

1. Add the `asm-writer` dependency to `crates/blitz-codegen` and a
   `code_sharing` module containing `ShareContract`, a per-function
   coordinator, accounting, diagnostics, and an off-by-default configuration.
   Keep it free of concrete ISA types.
2. Introduce a backend-local `SharingSafepoint` hook adjacent to the current
   `RegAllocW`/`BlitzW` adapters, not in `BlitzWriter`. It must expose
   `flush_for_call`, `invalidate_after_call`, helper-call emission, helper
   entry/body/return emission, and contract construction.
3. Add function begin/end lifecycle hooks to `WasmSink`/the ABI path as needed
   for staging and helper-area emission. Verify all error paths drain/restore
   or discard held blobs exactly once.
4. Instrument candidate rejection with structured test logging using the
   existing `PORTAL_LOG_JSON` / `PORTAL_LOG_BAT` facilities. Log reason,
   contract class, input/output byte counts, and share outcome; never log raw
   code bytes by default.
5. Add unit tests using a fake `RewindableCodeWriter` proving that a blob is
   opaque to the coordinator, contracts partition identical hashes, singletons
   restore inline, and repeated candidates generate exactly one helper.

**Exit criterion:** the generic machinery compiles and tests with sharing off;
normal native output is byte-identical when it is disabled.

### Phase 3 — one vertical slice: x86-64 SysV binary output

1. Start with `blitz-x86-64` SysV plus `IcedWriter`, because it has explicit
   marshalled-call lowering in `src/sysv.rs`, a regalloc-backed core, and
   direct binary/Unicorn coverage. Do not start with the CTX-stack-based naive
   or LFI paths.
2. Define the x86-64 v1 contract: same function/frame layout, empty WASM stack,
   flushed locals, no live allocated values, no control-flow/probe/exception
   labels in the candidate, and ABI-correct RSP alignment. Reserve any scratch
   registers needed by helper-call lowering just as probe paths currently do.
3. Place candidate anchors only around a short, deliberately selected
   straight-line integer subset (for example already-regalloc-covered
   constants/locals/arithmetic) between existing safe flush boundaries. Do
   not change the WASM dispatcher semantics.
4. Implement chosen layout strategy; generate helper labels/body/return and
   replacement direct calls through `call_label`. Ensure helpers cannot be
   reached by ordinary fallthrough and that unresolved helper calls are fixed
   by final label placement.
5. Add tests for duplicate candidates (smaller output, one helper/correct
   calls), singleton candidates (not larger under production staging),
   locals/empty stack, hash collision fallback, no sharing across different
   contracts, and execution in Unicorn. Retain an assembly-text inspection
   test even though text writers do not yet support rewriting.

**Exit criterion:** all x86-64 SysV existing tests pass; new execution tests
prove duplicates return to the correct continuation; configured repeated
corpora show nonnegative total size and at least one demonstrably smaller case.

### Phase 4 — AArch64 then RV64

1. Port AArch64 SysV/naive only after specifying which active ABI has the
   canonical flush and call boundary. Use `AArch64Writer` direct binary tests;
   account for 16-byte SP alignment and the existing 16-byte regalloc stack
   stride. Verify `BL`/`RET` helper behavior and branch reach or add a
   conservative out-of-range fallback.
2. Port RV64 after resolving JAL range and `ra`/SP ABI details. Use
   `RvAsmWriter` binary tests and Unicorn. Any long-range call sequence must
   be part of both the size model and canonical blob contract.
3. Keep RV32, ARM, i686, x86-64 naive, and all LFI paths disabled until each
   has a binary writer capability and a reviewed call safepoint. Respect
   ILP32's 8-byte WASM slots versus 4-byte host-pointer/SCR tables.
4. Re-run code-size and execution baselines for every supported backend. A
   backend may opt out permanently if its calling/stack model cannot meet the
   contract cheaply; generic writer support remains useful independently.

### Phase 5 — broaden only with proof

In order, consider: canonical local labels/fixups within blobs; explicitly
modeled branches/terminators; stack-carrying helper ABI; text-buffer adapter;
then cross-function helpers with a parameterized frame-independent ABI.
Each is a separate design/verification increment. Exception handling,
LFI bundle integrity, active probes, ambient/external relocation blobs, and
cross-function local layouts remain excluded until covered by their own
contracts and execution tests.

## Verification matrix

### asm-arch unit tests

For x86-64, AArch64, RV64, and RV32 binary writers:

- drain/append exact round-trip with no labels, backward labels, forward
  labels, unresolved externals, and labels after the anchor;
- rewind exact equivalence to a writer that never emitted the removed code;
- appending at a different offset correctly rebases all supported metadata;
- failures are atomic and labels are neither leaked nor accidentally reused;
- same semantic blob at different original offsets has one digest; distinct
  encodings/contracts do not; and forced digest collision invokes equality
  rejection rather than unsafe sharing;
- existing `into_bytes`, `into_parts`, and `into_parts_with_relocs` behavior
  retains no stale fixups or relocations.

Run each changed crate's tests and `cargo test --workspace` in `../asm-arch`.

### wasm-blitz tests

- `cargo build --workspace` and `cargo test -p portal-solutions-blitz-tests`;
- the existing binary paths in `e2e.rs` for x86-64/AArch64/RV64, including
  direct `IcedWriter`, `AArch64Writer`, and `RvAsmWriter` output;
- exact behavior for repeated arithmetic, repeated locals, loops/ifs rejected
  rather than shared, nested calls, return values, imports/relocations, and
  instrumentation enabled/disabled;
- output-size assertions that count helper/call overhead, plus a corpus summary
  showing number of candidates, rejects by reason, equivalence classes, shared
  bytes, added overhead, and net bytes saved;
- when a relevant clang cross-target is missing, use the existing
  `assemble_or_skip` pattern. Do not claim Linux or cross-toolchain coverage
  from host-only tests.

For every rollout, compare the passing/skipped test sets to the pre-change
baseline. `BLITZ_TRACE_UNICORN=1` is a diagnosis aid for any changed control
transfer. Use `PORTAL_LOG_JSON=1 PORTAL_LOG_BATCH=1` for compact structured
sharing traces.

## Non-goals and explicit failure behavior

- No semantic change to input WASM, no source/WASM IR deduplication, and no
  sharing merely because two textual instruction renderings look alike.
- No raw `Vec<u8>` exposure from the generic trait and no caller-written byte
  patching. Blob representations, label maps, relocation recipes, and hash
  canonicalization remain opaque.
- No use of a randomized `HashMap` hash as a stable code fingerprint.
- No implicit support for arbitrary `fmt::Write`, streams, LFI, exception
  handlers, probes, branches, relocations, or cross-function frames in v1.
- No fallback that emits a call when safepoint proof, blob transaction, or
  profitability accounting fails. Restore original bytes, record a rejection,
  and continue.

## Success criteria

The first released slice is successful when all of the following are true:

1. At least x86-64 `IcedWriter`, AArch64 `AArch64Writer`, and RV64
   `RvAsmWriter` implement one tested generic opaque rewind/drain trait in
   `asm-arch` without making streaming/text writers pretend to support it.
2. With sharing disabled, wasm-blitz native output and behavior remain
   unchanged.
3. With sharing enabled for its narrow x86-64 SysV slice, generated repeated
   straight-line WASM code is observably smaller after all helper/call costs,
   while singleton and ineligible code do not regress under the production
   policy.
4. Existing and new Unicorn execution tests prove the helper returns to the
   original continuation with correct values and preserved machine/WASM state.
5. Every expansion of eligibility is justified by an explicit
   `ShareContract`, byte-accounting test, and architecture-specific execution
   coverage rather than by optimistic byte-hash matching.
